## M1 — Безопасные дефекты аудита (поведение пользователя не меняется)

Разбито по под-группам; каждый пункт — отдельный коммит + тест/стенд-доказательство.

### A. Паники / неверный режим отказа
- `src/xswitcher.go:427` — `make(map[string][]string, len(t) - 4)`: короткий `[Actions]` даёт
  отрицательный cap → `panic: makeslice`. Фикс: убрать арифметику из cap (просто `make(map...)`).
  Тест: распарсить конфиг с `[Actions]` < 4 ключей → нет паники.
- `src/xswitcher.go:1808-1813` — top-level `recover()` глушит панику и systemd видит exit 0.
  Обсудить: печатать стек при `-d` и возвращать ненулевой exit-code. ⚠️ меняет контракт сервиса — вынести
  отдельным коммитом с явной пометкой, не в «молча-safe» кучу.

### B. Exec-подсистема (`exec/exec.go` + `Exec` в xswitcher.go)
- `xswitcher.go:1298-1302` — пустой `A.UID` → `user.Lookup("")` падает → любой `[Action.X] Exec=` без
  UID = silent no-op. Фикс: если `UID==""` — не ставить credentials (запуск от текущего пользователя);
  задокументировать дефолт. Юнит-тест.
- `exec.go max_reply` (`:24,169,177`) — никогда не выставляется → `io.CopyN(..., 0)` → `StdOut/StdErr`
  всегда пустые (результат Exec нигде не видно). Фикс: выставить разумный лимит / читать всё.
- `exec.go:121` таймаут: дефолт 100 + комментарий «Timeout = 1000 # 1 second» ⇒ замысел в ms, но цикл
  `Timeout*10 × 100ms` = секунды (×1000 от_intent). Фикс: привести единицу к ms консистентно + тест.
- `exec.go:87-88` — `StdoutPipe/StderrPipe` ошибки → nil-deref путь при последующем `io.CopyN`. Проверять err.
- `exec.go:120-162` — data race: goroutine таймаута читает `cmd.ProcessState`, `cmd.Wait()` пишет. Фикс:
  синхронизация / читать состояние после Wait. Доказательство: `go test -race` на харнесе Exec.

### C. Unchecked returns
- `xswitcher.go:1049,1055` — `XkbGetState/XkbLockGroup` коды возврата не проверяются → неудачное
  переключение группы молча. Минимум: лог по `-v/-d`. (Полный семантический фикс — в M2.)
- `xswitcher.go:1069-1073` — `sendKey` игнорит ошибки `kb.Up/Down/Sync` → сбои вирту-клавиатуры невидимы.
  Считать/логгировать.

### D. Корректность состояния
- Stale `EXTRA`: `testAction` (`:1389-1396`) ставит глобальный `EXTRA`, ветки `NewSentence/Compose`
  выходят без сброса → `RetypeWord` читает протухший `EXTRA`. Фикс: сброс/скоуп. Юнит-тест.
- `xswitcher.go:1476-1483` — `range ActSeq` (map) даёт недетерминированный порядок при нескольких
  совпавших правилах, оба трогает `EXTRA`. Фикс: детерминированный обход (сортировка ключей). Тест.

### E. Гигиена логов (keylogger-шум в stdout)
- Загейтить по `VERBOSE/DEBUG`: `:850,858,861` (=/* класс окна на каждую смену), `:1107,1134,1209`
  (RetypeWord-предупреждения), `:1418` (WTF no such action), device/watcher-болтовню `:1571…1870`.
- Отметить: `:1179-1198` под VERBOSE печатает сырые сканкоды набранного слова (чувствительный keylog-вывод)
  — оставить строго за гейтом, явно назвать в PR.

### F. Мёртвый код / rot (косметика, мелкими коммитами)

## M2 — #14: снимок раскладки на момент слова (семантика; ⚠️ требует sign-off на дизайн)

**Root cause (evidence):** ретайп направляет коды в группу, активную на момент реплея; `WORD` хранит только
`(code,value)` без штампа группы (`:1535-1537`); `Switch` (`:1219-1236`) делает слепой циклический сдвиг
`next = l+1`; на Wayland кэш `LANG` (`:1024-1038`) может пропустить шорткат и рассинхрониться. Модель
правильного поведения уже есть во workaround автора: `gnome3/switch.gnome:17-25` читает РЕАЛЬНУЮ текущую
группу (`g3kb-switch -p`) и ставит явную другую.

**Фикс:**
1. При пустом→первом ключе слова (в `checkAppend`/`newWord`) записать активную группу (`Language(-1)` на X11;
   на Wayland — перечитать источник, а не кэш). Хранить в `winBuffers` (вписывается в пер-оконную модель).
2. Целевая группа ретайпа = «не та, в которой слово НАБАРАЛИ», через явную read-back постановку, а не `+1`.
3. Default-конфиг не ломаем; семантика становится детерминированной.
**Доказательство:** новая фаза стенда — набрать слово в группе A, сменить раскладку внешним наблюдателем,
триггер → эмит должен лечь в ожидаемую группу; `analyze.py` сверяет поток. Негативный контроль на копии
`901511d` (снимка нет → падает ровно новая проверка).

## M3 — P1-6: механизм ретайпа через выделение (поведенческое; ⚠️ sign-off)

**Root cause:** `xswitcher.go:1145-1147` `for i<count-COMPOSE: pressKey(KEY_BACKSPACE)` — слепая пачка BS
на фиксированном `Keyboard.Delay=5ms` (10ms/key), без подтверждения, что приложение стёрло. Aborts при любом
BS внутри WORD (`:1133-1136`).

**Фикс:** заменить на структурное выделение слова + одно удаление: `Ctrl+Shift+Left` (или `Shift+Home` по
линии) затем один `BackSpace`/`Delete`. Оставить старый путь как config-переключатель (фолбэк для приложений,
не читающих selection).
**Ограничение честности:** стенд доказывает только ЭМИТИРОВАННУЮ последовательность EV_KEY, а не то, что
конкретный Chrome/терминал её корректно обработает — это записать явно. Доказательство пары прогонов + новый
`analyze.py`-кейс «выделение вместо пачки BS».

## M4 — #5: текст-для-Exec (дефект) + источник выделения (фича)

**Дефект (реальный, входит в M4a):** `Exec` при `SendBuffer="WORD"/"SENTENCE"` делает
`c.StdIn = fmt.Sprintf("%v", WORD)` → дамп `[]t_key` (`[{16 1}…]`), не текст. Фикс M4a: хелпер
`wordToText()/sentenceToText()` (рендер кодов в человекочитаемый текст по текущей раскладке) и подача его в
StdIn. Это чинит и уже штатный `Exec`+WORD. Юнит-тест на рендер (ASCII/US; кириллица — лимит scancodes).

**Фича M4b (выделение):** источник текста выделения. Есть `golang.design/x/clipboard` (юзается только в
`typeClipboard`). Добавить `SendBuffer="CLIPBOARD"` (`clipboard.Read(FmtText)`) и/или X PRIMARY fetch в cgo.
Переводчик = внешняя команда пользователя: xswitcher остаётся источником (выделение→stdin) и приёмником
(результат → `typeClipboard`). Границы фичи зафиксировать в PR: xswitcher НЕ переводит сам.
**Безопасность:** чтение буфера обмена/выделения — печать/перехват чувствительных данных; никаких логов тела.
